# Quick 260518-o48: Supporto invio email via SMTP (nodemailer) Summary

`sendEmail()` ora invia via SMTP nodemailer quando `SMTP_HOST` è configurato, con fallback invariato su Resend HTTP API; interfacce pubbliche preservate, nessun call-site modificato.

## Cosa è stato fatto

- **Task 1 — dipendenza nodemailer** (`9154855`): installati `nodemailer ^8.0.7` in `dependencies` (runtime server-side) e `@types/nodemailer ^8.0.0` in `devDependencies` via pnpm. Nessuna altra dipendenza toccata.
- **Task 2 — trasporto SMTP + fallback Resend** (`776fa06`): refactor di `src/lib/email.server.ts`:
  - `sendEmail()` diventa un dispatcher: instrada su `sendViaSmtp()` se `SMTP_HOST` è valorizzato, altrimenti su `sendViaResend()` se `RESEND_API_KEY` è valorizzato, altrimenti logga errore strutturato e ritorna `{ ok: false }`.
  - Nuova funzione privata `sendViaSmtp()`: legge `SMTP_HOST/SMTP_PORT/SMTP_USER/SMTP_PASS` da `process.env`, crea il transport con `nodemailer.createTransport`, calcola `secure = port === 465` (porta default 587 -> STARTTLS), invia con `transporter.sendMail`, ritorna `{ ok: true, id: info.messageId }`.
  - Percorso Resend estratto invariato in `sendViaResend()` (fetch a `https://api.resend.com/emails`, controllo `response.ok`, parsing `{ id: string }`).
  - Error handling: `catch (error: unknown)` + narrowing `instanceof Error`, log strutturato senza stack trace.
  - JSDoc del file aggiornato per descrivere la selezione del trasporto.

## Interfacce / contratti

- `SendEmailOptions` (`{ to, subject, html, replyTo? }`) e `SendEmailResult` (`{ ok, id? }`) **invariate**.
- Firma `sendEmail(SendEmailOptions) => Promise<SendEmailResult>` **invariata** — zero call-site modificati.

## Variabili d'ambiente

Nuove variabili lette (opzionali, attivano il percorso SMTP solo se `SMTP_HOST` è presente):

- `SMTP_HOST` — host SMTP (se assente -> fallback Resend)
- `SMTP_PORT` — porta SMTP (default `587`; `465` -> TLS implicito)
- `SMTP_USER` / `SMTP_PASS` — credenziali SMTP (se `SMTP_USER` assente, transport senza auth)
- `EMAIL_FROM` — mittente (già usato, riusato anche dal percorso SMTP)
