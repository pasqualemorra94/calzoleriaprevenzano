<objective>
Correggere un bug di schema Prisma sul modello `verification` (Better Auth) che rompe il flusso di reset password in produzione.

Purpose: In `prisma/schema.prisma` (riga 99) il campo `value` del modello `verification` è dichiarato `value String @unique`. Lo schema canonico di Better Auth NON prevede un vincolo unique su `verification.value`: Better Auth crea più righe `verification` (es. token di reset password) e il campo `value` può legittimamente ripetersi. Il vincolo causa un errore Prisma `P2002` ("Unique constraint failed on the fields: (`value`)") durante `prisma.verification.create()`, facendo rispondere `/api/auth/request-password-reset` con HTTP 500. Reset password rotto in produzione.

Output: Schema corretto + file di migrazione che droppa l'indice unique su `verifications.value` (in produzione verrà applicato da `npx prisma migrate deploy`, già nel CMD del Dockerfile).
</objective>
